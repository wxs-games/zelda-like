### 1.2 软件用途与主要功能

本软件是一款俯视视角的2D 动作冒险游戏，运行于 Android 移动平台。玩家操控角色
在森林等场景中探索，通过近战挥砍与弓箭射击两种攻击方式击败敌人，收集资源，
完成委托任务，并通过技能树系统提升角色能力。

主要功能模块包括：

1. **角色控制模块**：八方向移动、跳跃与落地、动画状态切换。
2. **战斗模块**：近战挥砍（含连段判定）、弓箭蓄力射击、命中判定与伤害结算、
   击退反馈、受伤与死亡处理。
3. **敌人AI 模块**：巡逻、警觉、追击三态行为切换，玩家探测与视野判定。
4. **物品与背包模块**：物品数据配置、背包槽位管理、使用效果结算、商店购买与出售。
5. **任务系统模块**：任务链定义、目标类型计数、进度追踪、完成条件判定与横幅提示。
6. **技能树模块**：技能前置依赖、可用点数管理、连锁解锁、属性加成应用。
7. **NPC 与对话模块**：对话树配置、条件分支、选项与状态推进。
8. **持久化模块**：游戏进度 JSON 序列化至本地磁盘、跨场景恢复、退出与切后台自动存档。
9. **移动端适配模块**：横屏锁定、帧率限制、后台暂停与存档、多点触控、虚拟摇杆、
   安全区适配。

## 二、技术架构

### 2.1 总体架构

本软件采用**泛型状态机 + 脚本化配置资产 + 事件解耦**三层架构，将易变的数值型数据
从代码中剥离，使同一套逻辑代码可通过配置调整玩法表现。

```
┌─────────────────────────────────────────────┐
│           GameRoot（持久单例）               │
│  GameBootstrap 守卫 · DontDestroyOnLoad│
└─────────────────────────────────────────────┤
│                 系统层│
│  GameInput · SaveSystem · DialogManager      │
│  QuestManager · SkillTreeManager · MobileRuntime│
├─────────────────────────────────────────────┤
│                 逻辑层                       │
│  PlayerController（状态机）                   │
│  EnemyController（状态机）                    │
│  InventoryManager · ExpManager               │
├─────────────────────────────────────────────┤
│                 配置层                        │
│  GameDatabase.asset│
│  ItemSO · SkillSO · QuestSO · DialogSO│
└─────────────────────────────────────────────┘
```

### 2.2 状态机设计

核心类 `StateMachine` 为泛型实现，通过泛型参数约束状态基类与上下文类型，
使玩家与敌人的状态逻辑复用同一套调度框架。

状态切换采用「当前状态退出 → 新状态进入」的标准生命周期，各状态类实现
进入、退出、逐帧更新三个阶段。玩家状态包括待机、移动、攻击、射击、
受击击退；敌人状态包括待机巡逻、追击。

### 2.3 配置驱动

`GameDatabase` 作为配置聚合根，在编辑器阶段由 `GameDatabaseBuilder` 扫描
工程资产自动生成，避免手工维护造成的遗漏与不一致。数据库在运行时提供
按 ID 与名称的双向索引，保证 O(1) 查找。

各配置项使用 `ScriptableObject` 派生类：物品、技能、任务、对话节点均为独立资产，
调整数值无需改动代码，重新生成数据库即可生效。

### 2.4 事件解耦

系统间通信采用 C# 事件而非直接引用。例如任务系统通过 `QuestManager` 暴露的
事件通知 UI 层更新横幅，避免 UI 直接轮询任务状态；玩家受伤通过
`PlayerHealth` 事件触发 UI 与 AI 反应。新增监听方无需修改发布方代码。

## 三、核心模块设计

### 3.1 角色控制模块

`PlayerController` 作为上下文对象持有点击、刚体、动画等引用，由状态机驱动。
输入层通过 `GameInput` 门面统一封装，屏蔽底层输入方案差异：键盘、虚拟手柄、
屏幕虚拟摇杆均映射到同一组语义动作（移动、攻击、射击、跳跃、交互）。

移动采用刚体速度驱动而非位置直接赋值，保证与碰撞体检测系统一致；
加入土狼时间与跳跃缓冲窗口以提升操作手感。

### 3.2 战斗模块

`PlayerCombat` 负责伤害结算，`PlayerAttackState` 管理挥砍连段。
连段判定基于输入时间窗口与当前连段计数，第三段触发特殊效果。

弓箭射击采用蓄力机制，`PlayerBow` 管理弓矢生成与飞行，`PlayerShootState`
处理蓄力状态转换。命中判定使用物理碰撞体检测，命中后依次触发受伤、
击退、死亡检查与经验结算。

### 3.3 敌人AI 模块

`EnemyController` 复用同一状态机框架，持有巡逻点集合。
`EnemyPlayerDetector` 负责玩家探测，使用距离判定与视野角度双条件。
状态切换策略为：未探测到玩家时巡逻，发现玩家进入追击，丢失目标返回巡逻。

### 3.4 任务系统模块

`QuestSO` 定义任务链与前置关系，`QuestObjective` 定义单个目标及其类型
（击杀敌人、收集物品、到达区域、交互）。`QuestManager` 维护运行时进度，
监听战斗与交互事件推进目标计数，达成条件后串联解锁后续任务。

### 3.5 技能树模块

`SkillTreeManager` 持有技能槽位集合，每个 `SkillSlot` 关联一个 `SkillSO` 并
记录前置技能槽列表。可用点数由可用点数管理器统一分配。

解锁规则包含两条：开局自动解锁无前置的根技能；某技能达到满级时，
仅解锁「将自身列为前置」的技能，避免越权解锁无关分支。
技能效果由 `SkillEffectApplier` 统一应用到属性。

### 3.6 持久化模块

`SaveSystem` 采用 JSON 文本格式序列化至应用私有目录。`SaveData` 为纯数据类，
字段覆盖玩家属性、背包、技能等级、任务进度与场景位置。

读档时按索引还原各槽位数据，并对玩家写入后清零刚体速度，
避免残留速度导致跨场景读档位置漂移。应用切至后台或退出时自动存档。

### 3.7 移动端适配模块

`MobileRuntime` 统一处理移动端运行时约束：设置目标帧率 60 帧并关闭垂直同步，
禁用系统休眠，允许多点触控。`OnApplicationPause` 与 `OnApplicationFocus`
回调中触发自动存档，并依据暂停前是否处于对话或面板状态决定是否恢复时间缩放，
避免恢复时误关面板。`SafeAreaFitter` 按屏幕安全区调整 UI 边距以适配刘海屏。

## 四、数据流程

### 4.1 配置生成流程

工程资产 → `GameDatabaseBuilder` 扫描并过滤空壳配置 → 生成
`GameDatabase.asset` → 运行时按索引反查。

过滤规则用于剔除名称为空或最大等级非正的占位资产，避免空引用导致运行时错误。

### 4.2 战斗结算流程

输入触发攻击状态 → 状态更新中开启攻击判定窗口 → 物理碰撞体检测命中 →
计算伤害并扣减生命 → 触发击退 → 击退结束判定死亡 → 死亡则结算经验并更新任务计数。

### 4.3 存档与读档流程

**存档**：读取玩家属性 → 读取背包槽位 → 读取技能等级与解锁状态 → 读取任务进度
→ 读取场景标识与坐标 → 序列化为 JSON → 写入磁盘并记录时间戳。

**读档**：校验文件有效性 → 反序列化 → 按索引还原各段数据 → 加载对应场景
→ 恢复玩家坐标并清零速度 → 刷新 UI 表现层。

## 五、运行环境与部署

### 5.1 目标平台

Android 移动平台，最低支持 API Level 23，目标架构 ARMv7 与 ARM64，
图形接口采用 Vulkan。

### 5.2 构建配置

应用标识 `com.stareco.zeldalike`，版本号 1.0.0，脚本后端 IL2CPP。
构建采用 Gradle 构建系统，包含场景清单、资源打包、签名与产物输出。

### 5.3 产物说明

构建产物为 APK 安装包，包含双架构原生库、程序集代码、资源索引与配置数据，
单包体积约 41MB。

## 六、软件特点

1. **配置与逻辑彻底分离**：数值型策划内容全部资产化，调整玩法无需改动代码，
   降低改动引入缺陷的概率。
2. **状态机框架复用**：玩家与敌人共用同一泛型状态机框架，新增状态只需实现接口，
   无侵入扩展。
3. **事件驱动解耦**：系统间通过事件通信，UI 与逻辑层可独立迭代。
4. **存档字段与代码分离**：存档结构与业务逻辑解耦，新增可持久化内容只需
   扩展数据类并补齐读写两处。
5. **移动端适配完整**：覆盖帧率控制、后台存档、安全区适配、虚拟摇杆等
   移动端特有问题。
